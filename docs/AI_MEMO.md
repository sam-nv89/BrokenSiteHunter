## 2026-02-03 23:46 | Уточнение Критических Аспектов

### Вопросы Пользователя

#### 1. Что такое "серая зона"?

**Ответ:**
"Серая зона" в скрапинге — это действия, которые:
- Технически возможны (данные публично доступны)
- Но юридически спорны (ToS запрещают автоматический сбор)
- Законодательство не определено однозначно

**Конкретные примеры:**
- Google Maps ToS запрещает scraping, но данные публичные
- GDPR требует согласия на сбор email в ЕС
- В РФ/СНГ бизнес-данные обычно не считаются персональными

**Стратегия минимизации рисков:**
1. Приоритет официальных API (Google Places API)
2. Собственный scraper только при исчерпании лимитов
3. Щадящий режим: 20-30 req/мин, ротация IP, соблюдение robots.txt
4. Фокус на бизнес-данные (не персональные)

**Реальные риски:**
- Блокировка IP: 30-50% вероятность → решение: ротация IP/VPN
- Судебный иск от Google: <1% вероятность для малого объема
- GDPR штраф: 5-10% если собираем данные ЕС → решение: не работаем с ЕС или используем API

**Вывод:** Работаем осознанно, используя API + аккуратный scraping

---

#### 2. Приоритет: Качество или Скорость?

**Ответ Пользователя:** "Качество И скорость!"

**Принятое Решение:**
Реализуем гибридную стратегию через параллелизацию:

**Архитектура "Качество + Скорость":**
1. **Layer 1:** Google Places API (2-3 мин для 100 лидов)
2. **Layer 2:** Параллельная обработка email enrichment (3 workers)
   - Метод 1: Парсинг сайта (60% покрытие)
   - Метод 2: WHOIS (15% покрытие)
   - Метод 3: Pattern Guessing (25% покрытие)
3. **Layer 3:** Параллельный technical audit (SSL + PageSpeed + Mobile)

**Результат:**
- 100 лидов за 15-20 минут
- Email покрытие: 70%+
- Technical audit: 100% охват
- Масштабирование: 1000 лидов за 3-4 часа (ночной запуск)

**Технические методы:**
- `asyncio` для параллельной обработки
- Batch requests для Lighthouse API
- Smart fallbacks (если email не найден — идем дальше)

#### 3. Согласие с Технологическим Стеком

**Ответ Пользователя:** "Не являюсь техническим специалистом - готов выслушать предложения"

**Обоснование Выбранного Стека:**

##### Python 3.11
**Почему:**
- Читаемый код (как английский язык)
- Богатейшая экосистема для scraping (scrapy, selenium, beautifulsoup)
- AI/ML ready для будущего расширения
- 2+ млн вопросов на Stack Overflow

**Альтернативы:** Go (сложнее), Node.js (менее подходит для scraping)

##### Streamlit (Web UI)
**Почему:**
- Zero HTML/CSS/JavaScript — всё на Python
- Built-in компоненты (progress bars, downloads, charts)
- Hot reload (изменили код → страница обновилась)
- Бесплатный хостинг на Streamlit Cloud

**Альтернативы:** React (требует JavaScript), Django (избыточно для MVP)

##### PostgreSQL (База данных)
**Почему:**
- Open source и бесплатный
- JSONB поддержка для сложных данных
- Full-text search встроенный
- Scales до миллионов записей
- Бесплатные managed варианты (Supabase, Railway)

**Для разработки:** SQLite (не требует установки сервера)

##### n8n (Workflow Automation)
**Почему:**
- Visual drag-and-drop интерфейс
- Self-hosted (бесплатный, нет лимитов)
- 400+ интеграций
- Cron scheduling для автоматизации

**Альтернативы:** Zapier (платный), Airflow (сложный)

##### Docker + Docker Compose
**Почему:**
- Работает везде одинаково (Windows/Linux/Mac)
- Один файл конфигурации для всего
- Легкий rollback к предыдущим версиям
- Изоляция сервисов

**Для пользователя это означает:**
- Нанял фрилансера → `docker-compose up` → всё работает
- Никаких "у меня работает, у тебя нет"
